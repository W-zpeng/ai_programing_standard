# 1.0 → 1.1 更新说明

正式更新路径，2026-10-30。目标为 1.1；VER 有不兼容变化。目录自包含完整目标增量和已知旧基线。适用于声明为 1.0 的项目，但并非文件匹配就能跳过源审核。

## source-review

确认项目来源版本、未完成迁移、当前配置和活动文档。按目标材料 migration/MIGRATION.md 的前置收束审核核实状态、引用、用户决定和证据范围。BASELINE.yaml 来自实际采用副本，不保证所有 1.0 相同；逐文件匹配，差异先区分定制和版本变体，无法判断不覆盖。项目版本与文件矛盾先报告。旧缺口不追认违规，重复 ID 按受控纠错保存原件并同步明确引用；未解决项按影响限制相关步骤。

## prepare

向用户说明目标、变更、转换/保留/跳过/待决和恢复限制，尊重已有授权。先保存源标准、受影响项目实例和恢复清单。按实际 records 路径创建迁移 CHG/必要 TASK 或项目允许的等价记录；禁用实体不自动启用。确认协调责任和暂停范围。

清单 path 均相对项目 .ai；每项 source 相对本更新目录。modify 以 baseline 为三方比较依据；add 若已存在先评估复用或合并。文件传输校验 after_sha256；本地保留的定制另记位置、合并依据和检查结果，不谎称合并文件等于官方哈希。先准备目标标准及实例转换结果，普通开发不能混用两版规则。

## intent

按 files/migration/FEATURE_MIGRATION.md A：从当前活动记录及相关用户表达恢复理解，按需要创建或复用唯一 USER_INTENT，不强制建空文档或全量扫描聊天；推断不能标为用户确认。同步入口及相关实体。普通未决不自动成为全局阻塞。

## learning

按同文档 B：无经验不建库，既有经验优先复用，适用经验才整理入口/详情/来源。候选和已支持经验明确区分；不修改工具配置，不将项目技术限制泛化。模板与规范更新不意味着所有历史经验都须重新处理。

## verification

按同文档 C：对活动/仍被引用的 VER 逐项审核。旧 passed/failed/inconclusive 保存为历史执行结果，不能直接映射生命周期。对象未知就保留未知；同文档多次执行按原证据粒度保存，不编造 Run。纯历史可保留旧格式，在迁移 CHG 记录转换/保留范围和解释边界，AI_ENTRY 提供指针。核对 TASK/BUG/CHG、索引和读取 VER.status 的本地工具；不凭 closed 宣称验证通过。

## closure

启用批次、里程碑和迁移前后收束审核，首轮针对当前范围，不要求改写全历史。检查启用实体、模板、入口、派生索引、证据及引用的正确性；旧状态扩展先理解，不能随意映射。角色目录、用户配置和历史记录不被标准文件覆盖。

所有已修复、未解决和未开展项向用户报告。业务记录不清未必阻止全部升级，但影响转换依据或目标解释时暂停相关步骤；目标文件完整与目标语义审核都通过才允许切换。

## switch

确认目标标准、已处理实例和本地工具检查通过。记录 switching，再同步项目采用版本字段为 1.1（PROJECT_PROFILE、AI_ANCHOR、index，保留其各自格式）以及入口。多文件不假定原子切换。复核后记录 completed、SESSION 和独立迁移审计，再恢复受影响工作。尚未解决限制保留；发布 1.1 不等于现有项目已经升级。

## recover

每一步按 CHECKPOINT_TEMPLATE 保存前置/后置条件、原件和写后校验。恢复先查实际文件：后置已满足则验证跳过，前置满足才执行，两者均不满足保留漂移并沟通；不重复创建 Run 或分配纠错 ID。源审核失效时复核受影响结论。

撤回时区分源纠错和版本转换，不能自动撤销独立确认的事实纠错；发现其他执行者后续修改不覆盖。已产生新版业务记录时先评估降级，不仅恢复版本字段，不连带回退业务代码。保留迁移和修复历史。

## 完成与边界

具体项目验证与回执不能省略。已知源副本的缺失来源、简写引用或历史异常按影响保留并报告，不补造。测试脚本仅为维护者验证材料，不是项目必须具备的工具。工具接入层需要另行调整时提示接入方，项目规范不识别提示词文件名。
