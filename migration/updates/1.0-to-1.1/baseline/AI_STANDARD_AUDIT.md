### 5.12 违规处理

AI 违规时，必须记录并纠正。

| 违规               | 处理                    |
| ---------------- | --------------------- |
| 未声明写入            | 创建 `INC-xxxx`，补声明，可回滚  |
| 未回执写入            | 补回执，记 `WAIVER`        |
| 静默 L2/L3         | 立即通知，创建 `INC-xxxx`，可回滚 |
| 未做影响分析           | 补做，记 `WAIVER`         |
| 未更新 `change_log` | 补更新，记 `WAIVER`        |
| 未写交接             | 补写，记 `WAIVER`         |
| 遍历全库             | 停止，改按查询路径             |
| 跳过接手流程           | 补做，记 `WAIVER`         |

规则：

- `INCIDENT` 是实体名称，具体记录使用 `INC-xxxx`。

- `INC-xxxx` 必须记录时间、范围、影响、纠正、预防。

- 重复违规必须升级处理。

- 违规不删除历史。

## 第 6 部分：可见性协议

### 6.10 违规处理

| 违规               | 处理                     |
| ---------------- | ---------------------- |
| 未声明写入            | 创建 `INC-xxxx`，补声明，可回滚   |
| 未回执写入            | 补回执，记 `WAIVER`         |
| 静默 L2/L3         | 立即通知，创建 `INC-xxxx`，可回滚  |
| 静默范围与声明不符        | 立即暂停，重新声明，创建 `INC-xxxx` |
| 静默授权未失效          | 立即宣告失效，创建 `INC-xxxx`    |
| 审计缺失             | 补写审计，创建 `INC-xxxx`      |
| 审计与回执不一致         | 立即纠正，创建 `INC-xxxx`      |
| 未更新 `change_log` | 补更新，记 `WAIVER`         |
| 回滚未记录            | 补记录，创建 `INC-xxxx`       |

规则：

- `INCIDENT` 是实体名称，具体记录使用 `INC-xxxx`。

- `INC-xxxx` 必须记录时间、范围、影响、纠正、预防。

- 重复违规必须升级处理。

- 违规不删除历史。

- 违规必须写入审计。

---

### 6.12 多 AI 并行

- 多个 AI 不共享静默授权。

- 多个 AI 不共享会话。

- 多个 AI 通过 `index.yaml` 和审计分片协调。

- 写入冲突时，以最后声明的变更集为准，冲突创建 `INC-xxxx`。

- 每个 AI 的变更集必须标注 `actor` 和 `session`。

- 禁止多个 AI 同时写同一实体而不声明。
