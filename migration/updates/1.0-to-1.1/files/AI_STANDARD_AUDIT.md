# AI_STANDARD_AUDIT

## 标识冲突与历史记录受控纠错

历史保留不等于永久容忍错误标识。已核实的重复 CHGSET 应主动整理，建立无歧义的当前引用；不能只登记问题后继续按歧义 ID 执行查询、转换或回退。本节是 CHANGE 中标识稳定和历史不可覆盖规则的有限例外，不是任意重写历史的许可，不新增实体。

1. **核实**：定位全部同 ID 条目及相关引用，结合原文件、条目位置、时间、关联对象、内容和上下文，区分同一事件重复记录与不同事件误用同 ID。不能只凭时间先后或文本相似度裁决。
2. **声明与保护**：向用户说明发现、拟修复范围及影响；遵循原有分级和已授予权限。修改前保存完整原件、位置及校验依据到 records 角色下的纠错辅助目录。原件不可变且可定位，不依赖 Git；不修改标准发布材料或其他只读来源。
3. **唯一标识**：若同 ID 对应不同事件，为已确认事件分配符合 CHGSET 格式的未占用标识；默认将歧义旧 ID 保留为历史查询键，不再作为可执行的唯一引用。原始时间与操作事实不变，映射明确新编号是纠错分配，不能被理解为新的业务事件或时间排序依据。分配前检查现有分片、索引、历史映射和待写计划，串行登记，禁止复用。若能证明仅为同一事件重复落档，则归并当前有效入口，保留全部原始证据，不伪造第二个事件。
4. **映射与修补**：在相关 CHG/SESSION 及独立纠错审计中记录“旧 ID + 原条目定位 + 内容依据 → 新唯一 ID”、原因、受影响文件和修复变更集。可修正工作中的审计副本及已确认的引用，但原件必须可还原；正文事实和原始证据不得趁机改写。不能全局字符串替换；同一个旧 ID 的不同引用可能指向不同事件。
5. **待决引用**：无法确定目标的引用保持原文，并在可发现的纠错映射中标注歧义、影响及后续动作。旧 ID 查询必须返回候选和待决提示，禁止静默跳转到任意一条。不得自动执行依赖歧义引用的回退或验收判断。
6. **复查**：检查有效标识唯一、已确认引用同步、未确认引用逐项列明、原件可恢复、索引和历史入口能定位映射。重复运行按映射和实际内容核对，不重复分配新 ID。处理中断或出现并行修改时保留现场，先复核受影响步骤，不覆盖他人修改。
7. **报告**：报告已修复、未解决、未开展、修复依据、影响及下一步；发现冲突和未完成项不得以静默模式隐藏。即使无修改或暂无法完成，也必须报告实际结果，不将“已登记”称为“已解决”。

纠错记录自身使用无冲突的新 CHGSET，先于修补建立，避免修复过程失去追踪。所需实体未启用时沿项目配置冲突流程处理，不擅自启用。原始事故是否构成违规按实际证据另行判断，不因整理历史就自动创建 INC。

> 从异常提炼经验时，采用 `AI_STANDARD_LEARNING.md` 第 5、7 节；事实继续保留在已有实体、SESSION 和审计中，指导不能替代违规纠正或验证证据。

### 5.12 违规处理

违规处理统一见本文件 6.10，不重复定义。

### 6.10 违规处理

| 违规               | 处理                     |
| ---------------- | ---------------------- |
| 未声明写入            | 创建 `INC-xxxx`，补声明，可回滚   |
| 未回执写入            | 补回执，记录实际违规（按实体启用配置）         |
| 静默 L2/L3         | 立即通知，创建 `INC-xxxx`，可回滚  |
| 静默范围与声明不符        | 立即暂停，重新声明，创建 `INC-xxxx` |
| 静默授权未失效          | 立即宣告失效，创建 `INC-xxxx`    |
| 审计缺失             | 补写审计，创建 `INC-xxxx`      |
| 审计与回执不一致         | 立即纠正，创建 `INC-xxxx`      |
| 未更新 `change_log` | 补更新，记录实际违规（按实体启用配置）         |
| 回滚未记录            | 补记录，创建 `INC-xxxx`       |

规则：

- `INCIDENT` 是实体名称，具体记录使用 `INC-xxxx`。

- `INC-xxxx` 必须记录时间、范围、影响、纠正、预防。

- 重复违规必须升级处理。

- 违规不删除历史。

- 违规必须写入审计。

### 6.12 多 AI 并行

- 多个 AI 不共享静默授权。

- 多个 AI 不共享会话。

- 多个 AI 通过 `index.yaml` 和审计分片协调。

- 发生写入冲突时，暂停受影响写入并保留各方变更；不得按声明先后自动覆盖。核对任务分工、依赖、实际修改内容和最新文件，独立工作可以继续。
- 可明确合并的非冲突内容按已有授权处理；需求、设计或责任边界分歧反馈给用户或其指定责任方裁决。处理后重新读取相关文档，按项目验证计划验证结果，并记录到相关 TASK、CHG、SESSION 和审计。
- 正常发现重叠不自动视为违规；已发生越界写入、未经允许覆盖或内容丢失时，记录 INC 并评估恢复。尚未解决的需求或设计分歧按现有 OPEN 流程处理。记录实体遵守项目启用配置，未启用时按配置冲突流程处理。

- 每个 AI 的变更集必须标注 `actor` 和 `session`。

- 禁止多个 AI 同时写同一实体而不声明。

### 异常与豁免的区别

实际违规按事实纠正和记录，INC 未启用时使用已有工作/会话记录并报告，不为记录而递归启用实体。WAIVER/OVR 只用于获准的限定范围偏离或覆盖，不把事后事故改写为事前授权，不更改证据结论。
