# 迁移演练与验收

> 1.1 演练指南。以下覆盖检查目标，实际完成范围以发布审核报告为准，不代表任意项目升级通过。演练使用隔离副本，保留运行前后文件及检查结果；不改实际项目。

## 场景与预期

| 场景 | 样例输入 | 操作/中断点 | 预期 |
|---|---|---|---|
| 普通旧项目 | 少量活动 TASK/REQ，无经验 | 评估意图与复盘初始化 | 有持续目标才建意图；无经验不建空库 |
| 多次旧验证 | 同 VER 含失败、通过及缺失对象版本 | 转换后重试同一步 | 保留原结果粒度，未知不补造，不重复追加 Run |
| 本地定制 | 旧基线、本地新增规则、目标规范不同 | 合并；再模拟旧基线缺失 | 已知定制保留；缺基线不猜测覆盖 |
| 意图矛盾 | 近期表达与旧 REQ 不同 | 初次整理 | 显示差异与来源，未确认部分不变成授权 |
| 已有经验体系 | 既有入口、详情、历史引用 | 整理及路径调整 | 优先复用，不复制全历史，链接可用 |
| 应用中断 | 若干文件已变、检查点未记完 | 再次接手 | 先核对内容；已完成步骤跳过，未知漂移暂停 |
| 切换中断 | profile 已变而 anchor/index 未变 | 接手普通开发请求 | 识别 switching，先完成/撤回切换，不混用 |
| 撤回及并行修改 | 更新后他人又改同一文件 | 恢复旧副本请求 | 保护后续修改，选择性恢复；迁移审计保留 |
| 新旧 VER 共存 | 活动 VER 已转、历史 VER 保留 | 查证据与运行本地校验器 | 按迁移清单解释，closed 不当作通过 |
| 升级后有新工作 | 新 Run 和业务修改已产生 | 请求降级 | 重新评估，不仅恢复版本字段，不连带回退代码 |

## 执行记录要求

受控纠错场景：不同事件误用同 ID 后获得唯一有效标识，已确认引用逐项修复、歧义引用保留待决；旧键不被静默重定向，重复执行不重复分配，原始历史可恢复。核对处理前后报告包含所有未解决/未开展项。保留历史与纠错恢复分别验证，不能只检查旧记录未丢失。

应覆盖的收束场景：源索引与实体不一致时先核实再转换；重复历史 ID 无法唯一定位时暂停相关步骤；缺失证据不补造通过结论；源审核后另有修改时重审受影响范围；目标格式正确但扩大验证结论时拒绝切换；独立源纠错不被迁移撤回自动抹除。既有模拟测试结果不证明这些新增审核场景已经通过。

每个场景记录：源文件快照、材料标识、操作步骤、实际结果、预期差异、证据位置、是否通过。真实目标更新未准备好时，只能标为规则推演或局部检查，不能宣称端到端升级通过。

恢复分支应覆盖：满足前置条件可执行；满足后置条件可验证跳过；两者均不满足停止并报告。还应核实新增文件已存在、重命名目标冲突和删除目标出现本地改动的处理。
