# 1.1 专项迁移方法

> 与 MIGRATION.md 和具体 UPDATE.yaml 配合使用；具体项目的采用权限和转换条件仍须评估。

## A. 用户意图与探索

评估：是否有持续目标、已有意图说明、跨会话恢复需要；读取当前任务、直接 REQ、近期实质决定的 SESSION/CHG/ADR，遇矛盾才扩大范围。

- 没有持续记录需要：跳过创建并记录理由，不生成空文档。
- 已有类似说明：比较职责与内容，复用或按确认方案整理，保留旧引用去向，不能建立互相竞争的两个当前理解。
- 需要新建：按 docs.roles.current 建立唯一 USER_INTENT.md，区分用户表达、旧文档决定、AI 解释和未知。来源缺失不等于事实错误；只沟通影响当前动作的歧义。
- 不把所有旧 OPEN 都搬成当前必答问题，不推断用户已授权实现，不要求重复确认全部历史。
- 同步 AI_ENTRY 和必要锚点指针；非实体路径不填进实体 ID 关系字段。理解变化确实影响已确定内容时才进入关联 CHG。

验收：接手者能定位当前目标、确认范围、歧义、允许和暂缓动作，以及来源。纯探索无需强制初始化；跳过问题不自动接受默认；探索产物不自动成为正式验收基线。

## B. 渐进式复盘指导

评估：是否有现成经验记录/指导，以及本次整理价值；不默认复盘全历史。

- 无经验：只更新规范与按需读取说明，不创建空库。
- 零散经验：选择与当前工作相关、具有明确触发和纠偏价值的内容；原始记录保留，形成入口与详情链接。
- 已有指导体系：评估能否直接继续使用，避免重复入口；路径改变保留去向和来源。
- 仅整理成候选不等于验证有效，不把一次事件泛化；已有有效状态要有依据，无法确定则标明证据有限。
- 入口/详情遵循 AI_STANDARD_LEARNING.md。未安装自动工具也应能通过文本导航使用，不改工具侧提示词。

验收：应触发情形可找到可执行指导，相似但不适用时不增加无关检查；出现反证能复审或停用；来源、合并去向和引用可访问；指导不覆盖当前意图或正式规范。

## C. VER 语义变化

这是状态字段的不兼容调整，1.1 明确要求评估迁移，不以小版本号掩盖。先清点活动 VER、仍支持当前验收的旧 VER、纯历史 VER、状态与正文冲突的 VER，以及读取 status 的工具。

- planned：核实后可保留 planned。
- executed：核实实际执行及后续工作，不能推断通过。
- passed/failed/inconclusive：保留为原执行结果；生命周期按是否仍需工作判断 active/closed，不机械映射。
- 已有多次可辨识执行时分别整理；仅有汇总结论时保留其原始粒度和限制，不编造次数、Run 时间、对象版本、环境或来源。
- 运行记录去重依据为原文位置/来源标识和内容依据，并记入转换表，Run-N 只是文件内编号。
- 当前结论只采用适用于当前对象与条件的证据；旧 passed 不能自动证明当前代码通过。closed 不表示通过。
- 纯历史可保留旧格式；迁移 CHG 记录保留的旧语义文件/范围、已转换清单、对应 CHGSET 和读取说明，不能仅以项目当前版本判断记录格式。
- 混合记录不能用统一新状态校验器直接拒绝；index 指向实体，当前 schema 解释依据可从保留在 AI_ENTRY 的迁移记录入口定位。
- 检查 TASK/BUG/CHG 的证据引用和本地脚本。迁移不自动撤销历史验收，但不得扩大证据适用范围。

验收：旧结果及来源可还原；重试只追加一次；更正保留旧文；引用可用；对象未知时不宣称当前通过；新旧格式按边界解释。

## D. 规则和入口同步

清理旧的逐项问卷、每次跳过创建 OPEN、SESSION 仅结束时写、将 OPEN 当作依赖满足的表述。更新入口和模板，适用性检查应覆盖实际本地定制，不只是关键词替换。

接入材料不纳入自动项目迁移。说明旧接入约束可能仍要求固定选项或完整引导，由用户/接入方决定是否另行调整，不要求标准识别特定提示词文件。

## E. 发布限制

新增阶段收束审核的采用：更新执行、检查清单、模板与入口；对当前活动批次及受影响导航建立首次审核范围，不要求追溯重审全项目历史。旧缺口按当时规则和实际证据解释，不自动追认违规。重复 CHGSET 按 AUDIT 受控纠错建立唯一有效标识并修复已确认引用，完整保留原件及旧新映射；未确认引用列为待决，不自动重定向。来源缺失应查找并报告，用户要求跳过时注明未开展；没有依据不能为迁移通过而补造。

核查首次审核能区分开发完成、验证和文档收束，不因 VER/INC 等未启用而强制新建实体，也不因生成审核记录递归启动全量审核。尚未解决的实质冲突记录为待决，暂停依赖它的动作，独立工作可继续。规范升级完成与业务批次审核完成分别报告。

正式路径见 updates/1.0-to-1.1/。其基线为实际采用副本，非所有 1.0 项目一致的证明。缺基线或存在本地差异时不得无条件覆盖，按迁移流程逐项处理。
